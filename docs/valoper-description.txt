Why we want to validate on gno.land: Proof of Contribution is the only validator selection model we have seen where the way in is building rather than bidding, and equal voting power means the set is judged on merit rather than stake. We also want to write Gno — it is the first contract language where our Go experience transfers directly, and realms publishing readable source is the property we most want in infrastructure we depend on.

Contributions to gno.land:

- gno forms, a realm that publishes forms and collects responses on chain with gnoweb as the only UI, so collecting structured input no longer needs a Web2 backend. Live at /r/nym-encapsulate001/forms, source at https://github.com/encapsulate-xyz/gnoforms

- gnolang/gno#6140 — reported that an unticked checkbox in a gno-form submits its value regardless, making every boolean parameter unconditionally true. Filed with an on-chain reproduction, the served HTML and a verified workaround.

- gnolang/gno#6141 — gno-select has no way to set its visible label, so users see parameter names where a question should be.

- gnoland-ansible, public deployment automation for gno.land nodes: https://github.com/encapsulate-xyz/gnoland-ansible

Both issues were found by building on the form layer rather than reading the code. We are continuing to work on gno forms and on the gnoweb form layer.
